# 상용 런칭과 수익모델 계획 (2026-11-22)

사장님 요청: "실제 상용 서비스로 런칭하기 위해 어떤 점들을 개선해야 할지, 수익모델은 어떻게 강화해야 할지 전략을 세워서 상·중·하로 나누고 상부터 구현·검증을 반복해 끝까지."

이 문서는 계획이다. 무엇을 실제로 만들었는지는 `MORNING_REPORT.md` 맨 위 '5차 작업 보고'와 `IMPLEMENTED.md`가 기준이다.

## 1. 지금 상태 한 줄 요약

놀이·경쟁·공유·복귀 장치는 이미 많다(4차까지). 출시를 막는 것은 **운영 장치**(오류를 모른다, 문의 창구가 없다, 점검 안내가 없다, 사업자 정보가 없다, 무료 요금제 한도)와 **돈을 받는 길이 하나도 없는 것**이다.

## 2. 수익모델 전략

### 2-1. 무엇을 팔 수 있나

이 게임이 가진 자산은 "사람들이 모이는 가상의 타임스퀘어에서 내 글과 사진이 큰 화면에 뜬다"는 경험이다. 돈을 낼 사람은 셋이다.

| 누가 | 무엇을 원하나 | 예 |
| --- | --- | --- |
| 가게·1인 사업자·크리에이터 | 값싸고 눈에 띄는 홍보, 링크·QR | 카페 오픈, 스마트스토어, 유튜브 채널 |
| 팬덤 | 좋아하는 사람의 생일·데뷔 축하를 크게 | 실제 타임스퀘어·지하철 생일 광고 문화 |
| 개인 | 고백, 생일, 합격 축하 | "○○야 생일 축하해" |

### 2-2. 세 갈래

1. **광고 판매(현금, 게임 경제와 분리) — 지금 만든다.**
   - 게임의 점령 칸(코인 경쟁)과 별도로 **광고 전용 화면**을 둔다. 코인으로는 못 사고, 신청과 운영자 승인으로만 걸린다. 그래서 '현금으로 게임 칸을 산다(Pay-to-win)'가 생기지 않고, 게임 아이템 판매도 아니다.
   - 사는 길: `/ads` 안내 페이지 → 신청서(상품, 날짜, 문구, 연락처) → 운영자가 관리자 화면에서 검토·견적·입금 확인 → 일정에 맞춰 송출 → 기간이 끝나면 정직한 수치 리포트.
   - 처음에는 **계좌이체·세금계산서로 수동 결제**한다. 카드 결제 연동(PG)은 사업자 등록·통신판매업 신고·PG 심사가 끝난 뒤다.
   - 가격은 코드에 지어내지 않는다. Worker 변수 `ADS_PRICES`가 없으면 페이지는 '견적 문의'로 보인다.
   - 상품: 광고 전용 화면 하루 단위, 생일·응원 패키지(같은 흐름, 문구 템플릿만 다름), 밤 9시 60초 전체 화면 스폰서.
   - 스위치 `ADS_ON`(정확히 `1`일 때만 켜짐). 꺼져 있으면 아무것도 바뀌지 않는다.
2. **코인 상점(꾸미기, 코인으로만) — 중에서 만든다.**
   - 이름표·발밑 링·택시·전광판 테두리 꾸미기를 코인으로 산다. 코인이 빠져나갈 곳(소모처)이 생겨 경제가 건강해지고, 모으는 재미가 생긴다.
   - 현금은 끼지 않는다. 나중에 유료 코인을 열 때 그대로 상품 목록이 된다.
3. **유료 코인 충전 — 이번에는 만들지 않고 준비 문서만.**
   - 게임 안 재화를 돈으로 팔면 게임물 등급분류, 미성년자 결제 한도, 청약철회·환불 정책, 결제대행 계약이 필요하다. 그리고 이 게임에는 코인 경매(점령)와 코인 상금 추첨이 있어서, 현금 코인이 들어오면 사행성 판단을 받을 위험이 커진다.
   - 그래서 순서는: 광고 판매로 먼저 매출 → 지표 관문(다음 날 재방문 35% 등, 기존 메모) 통과 → 법무 확인 → 추첨 정리 → 그때 충전.
   - 법률 자문은 아니다. 체크리스트를 문서로 남긴다.

### 2-3. 하지 않는 것

- 점령 칸을 현금으로 파는 것, 코인을 현금으로 바꾸는 것, 보상형 광고, 가짜 접속자 수, 확률형 뽑기.
- 리포트 숫자를 '공식 노출 수치'처럼 파는 것. 리포트에는 '게임이 센 수'라고 적는다.

## 3. 상·중·하

기준: **상** = 출시 전에 없으면 운영이 막히거나 돈을 받을 길이 없는 것, 지금 코드로 만들 수 있는 것. **중** = 출시 직후 매출·재방문을 키우는 것. **하** = 있으면 좋은 것.

### 상

| # | 항목 | 내용 |

| 상1 | 오류 수집 | 브라우저 오류(`window.onerror`, `unhandledrejection`)를 표본·크기 제한·속도 제한을 걸어 Worker로 보내고, 같은 오류끼리 묶어 관리자 화면 '오류' 탭에 보인다. 서버 예외도 같은 곳에. |
| 상2 | 문의하기 | 설정의 `문의하기`: 분류(버그, 계정·코인, 신고, 광고·제휴, 기타), 내용, 답장 이메일(선택). 관리자 '문의함'에서 보고 처리 완료로 표시. 개인정보처리방침에 문의 항목 추가. |

| 상6 | 광고 판매 흐름 | 위 2-2의 1번 전부: `/ads` 페이지, 신청서, 광고 전용 화면, 관리자 검토·일정·송출, 리포트, `ADS_ON`·`ADS_PRICES`, 약관·처리방침의 광고 조항. |

## 4. 주인만 할 수 있는 것 (코드로 못 함)

- **Cloudflare Workers 유료 요금제($5/월)와 `PLAN=paid`.** 무료는 하루 요청 10만 건이고 이 게임은 한 사람이 한 판에 수백 건을 쓴다. 하루 수백 명이면 예산 가드가 걸린다. 출시 전에 올리는 것을 권한다.
- 사업자 등록, 통신판매업 신고, `OPERATOR_INFO` 값.
- 광고 가격(`ADS_PRICES`), `ADS_ON` 켜기, 입금 계좌·세금계산서 처리.
- 외부 가동 감시 서비스 가입, Supabase 백업 확인(유료 플랜의 PITR 여부).
- 유료 코인을 열지와 법무 확인.

## 5. 진행 방식

상 → 중 → 하 순서로, 항목마다 서브 에이전트가 만들고 본 세션이 검토·합치기·브라우저 확인을 한다. 운영 DB SQL, 배포, 푸시는 사장님이 말할 때만 한다(이번 요청에는 없다). 결과는 `MORNING_REPORT.md` 맨 위 '5차 작업 보고'에 남긴다.
