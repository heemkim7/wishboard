# Phase 2 Relight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 전광판 수명을 3·6·12시간 만료에서, 하루 한 번 불 켜기로 72시간을 연장하는 방식으로 바꾼다.

**Architecture:** `relight_billboard(p_key, p_actor_id, p_slot_id)`는 코인을 움직이지 않는다. `lit_until`을 72시간 뒤로 밀고 `expires_at`을 그 값에 맞춰 옛 `live()`가 켜진 칸을 살아 있다고 보게 한다. 내 칸은 빛기둥과 미니맵 핀으로만 표시한다.

**Tech Stack:** `schema.sql`, `worker.js`, `timesSquare3d.js`, `ui.js`.

## Global Constraints

- Meter DO 일일 예산 가드는 80% lean, 95% hard를 유지한다. `PLAN=paid`를 넣지 않는다. Workers 계정은 운영자가 올리기 전까지 Free다. `env.PLAN === 'paid'`는 유료 전용 작업을 건너뛰는 런타임 검사로만 쓴다.
- Room DO WebSocket hibernation을 유지한다. 핑, 스태일, 알람 주기와, 사람이 없을 때 알람 해제를 지우지 않는다.
- 위치 패킷은 `v2: {t:'P', k, a:[x,y,...]}`다. 서버가 받는 기존 메시지는 `t:'p'`이고, 릴레이는 `t:'P'`다. 이 둘을 한 글자로 합치지 않는다. 같은 층, `NEAR_R` 1600 안을 우선하고 먼 피어는 `FAR_MS`로 줄인다. `net.js` 데드레커닝 1.15초를 유지한다.
- `/rt/guest`는 HMAC(`GUEST_KEY`)이다. Supabase 익명 가입으로 바꾸지 않는다.
- 내 캐릭터 위치는 로컬 입력만 쓴다. 서버 좌표로 내 플레이어를 덮어쓰지 않는다. 좌표 변환은 `toNetUnits` / `fromNetUnits`만 쓴다. `floor = 0`.
- 자유 텍스트 채팅은 없다. 리액션은 `{t:'E', k, e: 1~4}`다.
- 브라우저에는 publishable 키만 둔다. `service_role`을 코드에 넣지 않는다. `.dev.vars`를 읽거나 커밋하지 않는다. 시크릿 값을 채팅, 코드, 커밋 메시지에 적지 않는다.
- 지도는 OSM만 쓴다. `ts3d/nycmeta.js`를 손으로 고치지 않는다.
- `schema.sql`은 통째로 다시 실행한다. 변경은 멱등이다. `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION`, `DROP POLICY IF EXISTS`, `CREATE INDEX IF NOT EXISTS`, `INSERT ... ON CONFLICT DO NOTHING`. `DROP TABLE`은 없다. 시그니처가 바뀌는 함수만 `DROP FUNCTION IF EXISTS`로 그 시그니처를 지운 뒤 만든다.
- 캐시: 이번 태스크에서 바뀐 모듈의 import `?v=`와 `index.html`의 `main.js?v=`를 같은 토큰으로 함께 올린다.
- 태스크 안에서 `npx wrangler deploy`, Supabase SQL 실행, `.dev.vars` 읽기, `git push`를 하지 않는다.
- 테스트는 `node`로 직접 실행한다. `package.json`을 만들지 않는다. `test/cf-stub.mjs`와 `test/plaza.test.mjs` 방식을 따른다. `https://studio.wishboard.workers.dev`를 호출하지 않는다. 테스트는 프로덕션 Supabase에 점령·지급을 쓰지 않는다. 로컬 `wrangler dev`도 프로덕션 DB를 본다.
- 이름표 색은 재질 이름이 `Main`인 메시에만 칠한다.
- 원점은 7번가 × W 45th St. 북쪽은 −Z, 동쪽은 +X. 채널은 `chapel:square`부터 `chapel:square-8`. `CAP`은 50이다.

- [ ] **Step 3: Write minimal implementation**

설계 5.4의 `ALTER TABLE` 네 줄과 이력 테이블이 이미 있으면 `CREATE TABLE IF NOT EXISTS`는 건너뛰고 열만 `ADD COLUMN IF NOT EXISTS` 한다. 일회 이전:

```sql
UPDATE public.billboards SET lit_until = expires_at WHERE lit_until IS NULL;
```

```sql
CREATE OR REPLACE FUNCTION public.relight_billboard(p_key TEXT, p_actor_id TEXT, p_slot_id TEXT)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_secret TEXT;
  v_board public.billboards%ROWTYPE;
  v_today DATE := (timezone('Asia/Seoul', now()))::date;
BEGIN
  SELECT key_value INTO v_secret FROM public.app_secrets WHERE key_name = 'FLUSH_KEY';
  IF v_secret IS NULL OR p_key IS DISTINCT FROM v_secret THEN
    RAISE EXCEPTION 'Unauthorized worker key';
  END IF;
  SELECT * INTO v_board FROM public.billboards WHERE slot_id = p_slot_id FOR UPDATE;
  IF NOT FOUND OR v_board.holder_id IS DISTINCT FROM p_actor_id THEN
    RETURN jsonb_build_object('ok', false, 'error', 'holder');
  END IF;
  IF v_board.lit_on = v_today THEN
    RETURN jsonb_build_object('ok', true, 'lit_until', v_board.lit_until, 'lit_days', v_board.lit_days);
  END IF;
  UPDATE public.billboards
  SET lit_until = now() + interval '72 hours',
      expires_at = now() + interval '72 hours',
      lit_on = v_today,
      lit_days = lit_days + 1,
      updated_at = now()
  WHERE slot_id = p_slot_id
  RETURNING * INTO v_board;
  UPDATE public.profiles SET reputation = reputation + 1 WHERE actor_id = p_actor_id;
  INSERT INTO public.billboard_history (slot_id, holder_id, holder_name, line1, line2, line3, bid, event)
  VALUES (p_slot_id, v_board.holder_id, v_board.holder_name, v_board.line1, v_board.line2, v_board.line3, v_board.current_bid, 'relight');
  RETURN jsonb_build_object('ok', true, 'lit_until', v_board.lit_until, 'lit_days', v_board.lit_days);
END;
$$;
```

`protected_until`과 `current_bid`는 SET에 넣지 않는다. 소속 칸(`holder_id`가 `tribe:`)의 멤버 불 켜기는 `p2-tribe`가 이 함수에 `tribe_members` 조건을 추가한다. 이 계획에서는 보유자 본인만 통과한다.

`claim_billboard`의 `v_live`를 `holder_id IS NOT NULL AND lit_until > now()`로 바꾼다. `lit_until`이 null이면 `expires_at > now()`를 본다. 새 점령 직후 `lit_until = now() + interval '72 hours'`, `lit_days = 1`, `expires_at = lit_until`. S 720분, B 360분, C 180분 대입은 점령 경로에서 제거한다. 보호 분(S 120, B 60, C 30, `user:` +5)은 유지한다. `add_billboard_spent`는 `expires_at`만 바뀔 때 `spent`를 올리지 않는 경제 계획의 식을 유지한다.

`POST /rt/relight`는 Bearer로 `relight_billboard`를 호출하고 성공하면 Meter `touch(isoWeek(), actor)`를 `INSERT OR IGNORE` 한다. `EVENT_NAMES`에 `'relight'`를 추가한다.

72시간이 지난 행은 크론이 없다. 다음 점령 또는 이 함수가 아닌, Worker의 세계 읽기에서 `lit_until < now()`인 보유 칸을 `clear`로 비우는 RPC `clear_dark_boards(p_key text)`를 두고 `coin` 업데이트는 넣지 않는다. `p1-return`의 paid 크론이 이미 return만 하므로, 이 clear는 `scheduled`의 paid 분기 안에서 `relight` 계획의 호출로 추가한다. `PLAN !== 'paid'`이면 여전히 전체를 return 하므로, Free에서는 다음 점령 시도가 빈 칸 규칙(환불 0)으로 처리한다. `clear_dark_boards`는 paid 크론에서만 돌아도 되고, 점령 SQL은 `lit_until`이 과거면 이미 빈 칸으로 본다.
