# Phase 4 Monetize Design And Legal Note Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 꾸미기 상점과 시즌 패스의 코인 가격, 그리고 유료화 전에 확인할 법무 항목을 설계 메모로 고정한다. 상품 코드와 결제 코드는 만들지 않는다.

**Architecture:** 산출물은 `docs/superpowers/specs/2026-11-15-monetize-legal-note.md` 하나다. `schema.sql`, `balance.js`, `worker.js`에 가격이나 SKU를 넣지 않는다. 설계 9장과 5.2의 이름을 그대로 쓴다.

**Tech Stack:** Markdown 메모와 `node --test`. 결제 SDK 없음.

## Global Constraints

- Meter DO 일일 예산 가드는 80% lean, 95% hard를 유지한다. `PLAN=paid`를 넣지 않는다. Workers 계정은 운영자가 올리기 전까지 Free다. `env.PLAN === 'paid'`는 유료 전용 작업을 건너뛰는 런타임 검사로만 쓴다.
- Room DO WebSocket hibernation을 유지한다. 핑, 스태일, 알람 주기와, 사람이 없을 때 알람 해제를 지우지 않는다.
- 위치 패킷은 `v2: {t:'P', k, a:[x,y,...]}`다. 서버가 받는 기존 메시지는 `t:'p'`이고, 릴레이는 `t:'P'`다. 이 둘을 한 글자로 합치지 않는다. 같은 층, `NEAR_R` 1600 안을 우선하고 먼 피어는 `FAR_MS`로 줄인다. `net.js` 데드레커닝 1.15초를 유지한다.
- `/rt/guest`는 HMAC(`GUEST_KEY`)이다. Supabase 익명 가입으로 바꾸지 않는다.
- 내 캐릭터 위치는 로컬 입력만 쓴다. 서버 좌표로 내 플레이어를 덮어쓰지 않는다. 좌표 변환은 `toNetUnits` / `fromNetUnits`만 쓴다. `floor = 0`.
- 자유 텍스트 채팅은 없다. 리액션은 `{t:'E', k, e: 1~4}`다.
- 브라우저에는 publishable 키만 둔다. `service_role`을 코드에 넣지 않는다. `.dev.vars`를 읽거나 커밋하지 않는다. 시크릿 값을 채팅, 코드, 커밋 메시지에 적지 않는다.
- 지도는 OSM만 쓴다. `ts3d/nycmeta.js`를 손으로 고치지 않는다.
- `schema.sql`은 통째로 다시 실행한다. 변경은 멱등이다. `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION`, `DROP POLICY IF EXISTS`, `CREATE INDEX IF NOT EXISTS`, `INSERT ... ON CONFLICT DO NOTHING`. `DROP TABLE`은 없다. 시그니처가 바뀌는 함수만 `DROP FUNCTION IF EXISTS`로 그 시그니처를 지운 뒤 만든다.
- 캐시: 이번 태스크에서 바뀐 모듈의 import `?v=`와 `index.html`의 `main.js?v=`를 같은 토큰으로 함께 올린다. 이 계획은 JS를 바꾸지 않으므로 토큰을 올리지 않는다.
- 태스크 안에서 `npx wrangler deploy`, Supabase SQL 실행, `.dev.vars` 읽기, `git push`를 하지 않는다.
- 테스트는 `node`로 직접 실행한다. `package.json`을 만들지 않는다. `test/cf-stub.mjs`와 `test/plaza.test.mjs` 방식을 따른다. `https://studio.wishboard.workers.dev`를 호출하지 않는다. 테스트는 프로덕션 Supabase에 점령·지급을 쓰지 않는다. 로컬 `wrangler dev`도 프로덕션 DB를 본다.
- 이름표 색은 재질 이름이 `Main`인 메시에만 칠한다.
- 원점은 7번가 × W 45th St. 북쪽은 −Z, 동쪽은 +X. 채널은 `chapel:square`부터 `chapel:square-8`. `CAP`은 50이다.

## 코인 상점

현금이 아닌 코인 가격만 적는다. `p2-identity`가 이미 시드하는 행과 같은 id다.

| cosmetic id | kind | grant_via 오늘 | 나중에 코인 가격 |
| --- | --- | --- | --- |
| `hat_ribbon` | `hat` | `attend7` | 400 |
| `cab_yellow` | `cab` | `attend7` | 800 |
| `frame_streak` | `frame` | `attend7` | 600 |

시즌 패스는 코인 2,000이다. 구매가 생기면 `spend_plaza` reason `pass`로 빼고, 그 시즌의 `cosmetics.season` 행을 `inventory`에 넣는다. `equip_cosmetic(p_key, p_actor_id, p_cosmetic_id)`는 그대로 장착에 쓴다. 출석으로 이미 가진 행은 다시 사지 않는다.

`SHOP`이라는 이름의 객체를 `balance.js`에 넣는 일은 유료화 착수 때다. 이 메모가 그 숫자의 원본이다.

## 법무 확인

변호사 또는 등급 담당이 확인하기 전에는 체크를 닫지 않는다.

- [ ] 게임물 등급분류. 웹 게임으로 볼 때 등급 신청이 필요한지, 사행성 표시가 등급과 따로인지.
- [ ] `sell_coins_to_advertiser`. 이용자가 고른 전광판 보유자에게 코인 10, 20, 50을 옮긴다. 환금·선불전자지급 해당 여부를 확인한다. 함수는 유지하고, 이 메모만 목록에 올린다.
- [ ] 추첨 고지. 버킷(5분)당 당첨 번호는 1에서 15 중 하나이고 상금은 25코인이다. 화면 문구는 `추첨`이다. `복권`과 `잭팟`은 1단계에서 빼기로 이미 정해져 있다. 확률 문장을 약관과 추첨 UI에 둘지 확인한다.
- [ ] 만 14세. 이메일 가입의 체크만 유지한다. 게스트 플레이를 14세 미만에게 열어도 되는지 확인한다.
- [ ] 사진·스냅샷 초상. 전광판 사진과 `/rt/snap` JPEG에 타인의 얼굴이 들어갈 수 있다. 약관에 없는 처리 목적을 유료화 때 `legal.js`와 맞춘다.
- [ ] 상표. 타임스퀘어, 브랜드, 아이돌 이름이 이용자 문구로 올라간다. 금칙어와 신고로 충분한지, 별도 권리 처리가 필요한지.

## 하지 않는 것

- 슬롯은 현금으로 팔지 않는다. 자리는 코인과 소속 모금으로만 연다.
- 현금 SKU, 카드 결제, 앱스토어 인앱, 보상형 광고, 스폰서 칸 판매 코드는 만들지 않는다.
- 스폰서 칸이 필요하면 관리자가 SQL로 `billboards` 표시만 한다. 저장소 마이그레이션에는 넣지 않는다.
- `legal.js`의 "유료 서비스" 문장과 "코인은 현금이 아니다"를 고치는 일은 유료화 착수 때다. 이 메모를 쓰는 동안 `legal.js`를 열지 않는다.
