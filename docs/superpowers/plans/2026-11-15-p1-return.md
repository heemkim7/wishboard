# Phase 1 Return Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 출석을 서버 7일 사다리로 저장하고, 자리를 비운 사이 온 일을 수신함에 남기며, 웹 푸시는 유료 플랜에서만 보낸다.

**Architecture:** `touch_attend(p_key, p_actor_id)`가 `profiles.attend_streak`와 `attend_last`를 갱신한다. 수신함은 `inbox` 테이블과 `{t:'INBOX'}`다. `scheduled`는 `env.PLAN !== 'paid'`이면 즉시 return 한다. 7일째 꾸미기 지급은 `p2-identity`가 이 함수에 얹는다. 이 계획은 inventory에 insert하지 않는다.

**Tech Stack:** `push.js`, `inbox.js`, `sw.js`, `worker.js`, `schema.sql`, `wrangler.jsonc`.

## Global Constraints

- Meter DO 일일 예산 가드는 80% lean, 95% hard를 유지한다. `PLAN=paid`를 넣지 않는다. Workers 계정은 운영자가 올리기 전까지 Free다. `env.PLAN === 'paid'`는 유료 전용 작업을 건너뛰는 런타임 검사로만 쓴다.
- Room DO WebSocket hibernation을 유지한다. 핑, 스태일, 알람 주기와, 사람이 없을 때 알람 해제를 지우지 않는다.
- 위치 패킷은 `v2: {t:'P', k, a:[x,y,...]}`다. 서버가 받는 기존 메시지는 `t:'p'`이고, 릴레이는 `t:'P'`다. 이 둘을 한 글자로 합치지 않는다. 같은 층, `NEAR_R` 1600 안을 우선하고 먼 피어는 `FAR_MS`로 줄인다. `net.js` 데드레커닝 1.15초를 유지한다.
- `/rt/guest`는 HMAC(`GUEST_KEY`)이다. Supabase 익명 가입으로 바꾸지 않는다.
- 내 캐릭터 위치는 로컬 입력만 쓴다. 서버 좌표로 내 플레이어를 덮어쓰지 않는다. 좌표 변환은 `toNetUnits` / `fromNetUnits`만 쓴다. `floor = 0`.
- 자유 텍스트 채팅은 없다. 리액션은 `{t:'E', k, e: 1~4}`다.
- 브라우저에는 publishable 키만 둔다. `service_role`을 코드에 넣지 않는다. `.dev.vars`를 읽거나 커밋하지 않는다. 시크릿 값을 채팅, 코드, 커밋 메시지에 적지 않는다.
- 지도는 OSM만 쓴다. `ts3d/nycmeta.js`를 손으로 고치지 않는다.
- `schema.sql`은 통째로 다시 실행한다. 변경은 멱등이다. `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION`, `DROP POLICY IF EXISTS`, `CREATE INDEX IF NOT EXISTS`, `INSERT ... ON CONFLICT DO NOTHING`. `DROP TABLE`은 없다. 시그니처가 바뀌는 함수만 `DROP FUNCTION IF EXISTS`로 그 시그니처를 지운 뒤 만든다.
- 캐시: 이번 태스크에서 바뀐 모듈의 import `?v=`와 `index.html`의 `main.js?v=`를 같은 토큰으로 함께 올린다.
- 태스크 안에서 `npx wrangler deploy`, Supabase SQL 실행, `.dev.vars` 읽기, `git push`를 하지 않는다.
- 테스트는 `node`로 직접 실행한다. `package.json`을 만들지 않는다. `test/cf-stub.mjs`와 `test/plaza.test.mjs` 방식을 따른다. `https://studio.wishboard.workers.dev`를 호출하지 않는다. 테스트는 프로덕션 Supabase에 점령·지급을 쓰지 않는다. 로컬 `wrangler dev`도 프로덕션 DB를 본다.
- 이름표 색은 재질 이름이 `Main`인 메시에만 칠한다.
- 원점은 7번가 × W 45th St. 북쪽은 −Z, 동쪽은 +X. 채널은 `chapel:square`부터 `chapel:square-8`. `CAP`은 50이다.

```sql
CREATE OR REPLACE FUNCTION public.touch_attend(p_key TEXT, p_actor_id TEXT)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_secret TEXT;
  v_last DATE;
  v_streak INT;
  v_today DATE := (timezone('Asia/Seoul', now()))::date;
  v_amount INT;
  v_ladder INT[] := ARRAY[10, 12, 15, 20, 30];
BEGIN
  SELECT key_value INTO v_secret FROM public.app_secrets WHERE key_name = 'FLUSH_KEY';
  IF v_secret IS NULL OR p_key IS DISTINCT FROM v_secret THEN
    RAISE EXCEPTION 'Unauthorized worker key';
  END IF;
  INSERT INTO public.profiles (actor_id) VALUES (p_actor_id) ON CONFLICT (actor_id) DO NOTHING;
  SELECT attend_last, attend_streak INTO v_last, v_streak FROM public.profiles WHERE actor_id = p_actor_id FOR UPDATE;
  IF v_last = v_today THEN
    RETURN jsonb_build_object('ok', false, 'error', 'attended');
  END IF;
  IF v_last = v_today - 1 THEN
    v_streak := COALESCE(v_streak, 0) + 1;
  ELSE
    v_streak := 1;
  END IF;
  v_amount := v_ladder[LEAST(v_streak, 5)];
  UPDATE public.profiles SET attend_streak = v_streak, attend_last = v_today WHERE actor_id = p_actor_id;
  RETURN jsonb_build_object('ok', true, 'streak', v_streak, 'amount', v_amount, 'last', v_today);
END;
$$;
```

`worker.js`의 `attend` 분기는 `grantFinal(a, PAY.attend)` 대신 `touch_attend`를 호출한다. `ok`가 아니면 `ag`를 올리지 않고 return false. `ok`면 `amount`만큼 `grantFinal`하고 피버를 곱하지 않는다. S6에서 첫날 출석 기대가 30이면, RPC 없이 도는 단위 테스트는 fetch를 모킹해야 한다. 테스트 더블이 `touch_attend`를 `{ ok:true, amount:10, streak:1 }`로 주면 출석 크레딧은 10이다. `test/plaza.test.mjs`의 S6 출석 assertion을 그 더블에 맞춘다. 피버 중에도 10이지 20이 아니다.

달력 UI는 `ui.js` 미션 시트에 7칸을 그린다. 데이터는 `GET`이 아니라 출석 `PAY`에 실어 주지 않는다. `touch_attend` 결과를 `bonus` 응답으로 소켓에 보낼 수 없으므로, `attend` 성공 시 `{t:'PAY', kind:'attend', amount, key:String(streak)}`를 보낸다. `key`는 설계 6.2의 선택 필드다.

const COPY = {
  taken: (m) => `${m.from_name}님이 ${m.slot_id}을 가져갔어요`,
  cheer: (m) => `응원 ${m.phrase}번이 도착했어요`,

  tribe: () => '이번 주 소속 결과가 나왔어요',
  ball: () => '21시 볼 드랍이 곧 시작돼요',
};

export function applyInboxPush(msg) {
  return (COPY[msg?.kind] || (() => ''))(msg);
}

export async function loadInbox() {
  const r = await fetch('/rt/inbox', { headers: { authorization: 'Bearer ' + (localStorage.getItem('masil_gt') || '') } });
  const data = await r.json().catch(() => ({ items: [] }));
  return Array.isArray(data.items) ? data.items.slice(0, 20) : [];
}

- [ ] **Step 3: Write minimal implementation**

```js
export function installHint(env) {
  if (env?.ios && !env?.standalone) return '홈 화면에 추가한 뒤 이 버튼을 누르세요';
  return '';
}

export async function subscribePush() {
  const hint = installHint({
    ios: /iPhone|iPad/.test(navigator.userAgent),
    standalone: window.matchMedia('(display-mode: standalone)').matches || navigator.standalone === true,
  });
  if (hint) return { ok: false, hint };
  const perm = await Notification.requestPermission();
  if (perm !== 'granted') return { ok: false, hint: '' };
  const reg = await navigator.serviceWorker.ready;
  const key = await fetch('/rt/push/key').then((r) => r.json());
  const sub = await reg.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: key.k });
  const json = sub.toJSON();
  await fetch('/rt/push', { method: 'POST', headers: { 'content-type': 'application/json', authorization: 'Bearer ' + localStorage.getItem('masil_gt') }, body: JSON.stringify({ s: json }) });
  return { ok: true, hint: '' };
}
```

`subscribePush`는 클릭 핸들러에서만 호출한다. `manifest.webmanifest`의 `display`는 `standalone`을 유지한다.

`sw.js`에 `push` 리스너를 추가한다. 수신 즉시 `showNotification`을 호출한다. 제목은 `모두의 전광판`, 본문은 서버 payload의 `body`. 사용자가 쓴 문구는 본문에 없다.

`wrangler.jsonc`의 `triggers.crons`가 없으면 배열을 만들고 `"5 * * * *"`만 넣는다. 기존 배열이 있으면 그 문자열을 추가하고 통째로 교체하지 않는다.

`worker.js` `scheduled`는 맨 앞에서 `if (env.PLAN !== 'paid') return;` 한다. paid일 때만 `push_subs`에서 어두운 칸과 안 읽은 `taken` `cheer`를 `PUSH_N`(40)까지 보낸다. 404와 410은 그 endpoint 행을 지운다. 본문은 설계 5.5 템플릿이다. `aes128gcm` 암호화는 WebCrypto만 쓰고 npm `web-push`는 넣지 않는다. 암호화 헬퍼 `encryptPush(sub, bytes)`를 `worker.js`에 두고, 테스트는 `PLAN !== 'paid'` 가드만 잠근다. 벡터가 로컬 WebCrypto에서 실패하면 발송을 건너뛰고 수신함은 남긴다.

알림 동의 버튼은 `setQuietBlock`이 false이고 공유 시트를 닫은 뒤에만 연다. 성공하면 `push_on` 이벤트를 보낸다.
