# Phase 2 Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 레벨과 명성과 보관함을 서버에 두고, 고양이와 곰을 켜며, 이름표 색은 `Main` 재질에만 칠한다.

**Architecture:** `equip_cosmetic(p_key, p_actor_id, p_cosmetic_id)`가 장착을 바꾼다. `speciesId`는 1·2·3만 받고 그 외는 1이다. 털·배·발 재질 이름은 `Coat` `Fur` `Belly` `Paw`이고 `Main`으로 바꾸지 않는다. `Mousey`의 `Ch14_Body`도 `Main`으로 바꾸지 않는다.

**Tech Stack:** `schema.sql`, `worker.js`, `profile.js`, `ts3d/avatars.js`, `ui.js`.

## Global Constraints

- Meter DO 일일 예산 가드는 80% lean, 95% hard를 유지한다. `PLAN=paid`를 넣지 않는다. Workers 계정은 운영자가 올리기 전까지 Free다. `env.PLAN === 'paid'`는 유료 전용 작업을 건너뛰는 런타임 검사로만 쓴다.
- Room DO WebSocket hibernation을 유지한다. 핑, 스태일, 알람 주기와, 사람이 없을 때 알람 해제를 지우지 않는다.
- 위치 패킷은 `v2: {t:'P', k, a:[x,y,...]}`다. 서버가 받는 기존 메시지는 `t:'p'`이고, 릴레이는 `t:'P'`다. 이 둘을 한 글자로 합치지 않는다. 같은 층, `NEAR_R` 1600 안을 우선하고 먼 피어는 `FAR_MS`로 줄인다. `net.js` 데드레커닝 1.15초를 유지한다.
- `/rt/guest`는 HMAC(`GUEST_KEY`)이다. Supabase 익명 가입으로 바꾸지 않는다.
- 내 캐릭터 위치는 로컬 입력만 쓴다. 서버 좌표로 내 플레이어를 덮어쓰지 않는다. 좌표 변환은 `toNetUnits` / `fromNetUnits`만 쓴다. `floor = 0`.
- 자유 텍스트 채팅은 없다. 리액션은 `{t:'E', k, e: 1~4}`다.
- 브라우저에는 publishable 키만 둔다. `service_role`을 코드에 넣지 않는다. `.dev.vars`를 읽거나 커밋하지 않는다. 시크릿 값을 채팅, 코드, 커밋 메시지에 적지 않는다.
- 지도는 OSM만 쓴다. `ts3d/nycmeta.js`를 손으로 고치지 않는다.
- `schema.sql`은 통째로 다시 실행한다. 변경은 멱등이다. `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION`, `DROP POLICY IF EXISTS`, `CREATE INDEX IF NOT EXISTS`, `INSERT ... ON CONFLICT DO NOTHING`. `DROP TABLE`은 없다. 시그니처가 바뀌는 함수만 `DROP FUNCTION IF EXISTS`로 그 시그니처를 지운 뒤 만든다.
- 캐시: 이번 태스크에서 바뀐 모듈의 import `?v=`와 `index.html`의 `main.js?v=`를 같은 토큰으로 함께 올린다.
- 태스크 안에서 `npx wrangler deploy`, Supabase SQL 실행, `.dev.vars` 읽기, `git push`를 하지 않는다.
- 테스트는 `node`로 직접 실행한다. `package.json`을 만들지 않는다. `test/cf-stub.mjs`와 `test/plaza.test.mjs` 방식을 따른다. `https://studio.wishboard.workers.dev`를 호출하지 않는다. 테스트는 프로덕션 Supabase에 점령·지급을 쓰지 않는다. 로컬 `wrangler dev`도 프로덕션 DB를 본다.
- 이름표 색은 재질 이름이 `Main`인 메시에만 칠한다.
- 원점은 7번가 × W 45th St. 북쪽은 −Z, 동쪽은 +X. 채널은 `chapel:square`부터 `chapel:square-8`. `CAP`은 50이다.

설계 5.2 DDL을 `schema.sql`에 그대로 넣는다. 시드:

```sql
INSERT INTO public.cosmetics (id, kind, grant_via) VALUES
  ('hat_ribbon', 'hat', 'attend7'),
```

`equip_cosmetic`은 그 계정의 `inventory`에 행이 있을 때만 `equipped`를 켠다. 같은 `kind`의 다른 행은 `equipped = false`로 끈다. 없으면 `{ ok:false, error:'missing' }`.

`touch_attend`가 streak를 7의 배수로 바꾼 그 호출에서, 세 cosmetic id가 `inventory`에 없으면 한 번씩 insert한다. 이미 있으면 건너뛴다. `p1-return`의 함수 본문 끝, `RETURN` 앞에 그 INSERT를 넣는다. 출석이 7, 14, 21…일 때마다 빠졌던 행만 채운다.

`profile.js`:

```js
export function setSpecies(id) {
  const n = Math.floor(Number(id));
  return n === 2 || n === 3 ? n : 1;
}

export async function loadProfile() {
  const r = await fetch('/rt/profile', { headers: { authorization: 'Bearer ' + localStorage.getItem('masil_gt') } });
  return r.json();
}

export async function equip(cosmeticId) {
  const r = await fetch('/rt/equip', {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: 'Bearer ' + localStorage.getItem('masil_gt') },
    body: JSON.stringify({ cosmetic_id: cosmeticId }),
  });
  return r.json();
}
```

`GET /rt/profile`은 `{ level, reputation, species, equip }`를 반환한다. `equip`은 장착된 cosmetic id 최대 4개. `level`은 `Math.min(99, 1 + Math.floor(reputation / 10))`과 같은 SQL `least(99, 1 + reputation / 10)`이다. `POST /rt/equip` `{ cosmetic_id }`는 `equip_cosmetic`을 호출한다. 종 변경은 `POST /rt/profile` `{ species }`로 `profiles.species`를 `setSpecies`와 같은 1·2·3 규칙으로 저장한다.

입장 `ok`에 `av`와 `equip`을 실어 준다. Room은 `tr`로 받은 `av`와 `equip`을 프로필 캐시 값으로 덮어쓴다.

- [ ] **Step 3: Write minimal implementation**

`ts3d/avatars.js`의 `SPECIES`에 두 항목을 추가한다. `speciesId`는 `setSpecies`와 같이 2와 3만 통과시킨다. 로더는 id 2에 `Cat.glb`, id 3에 `Bear.glb`를 요청한다. 클립 이름은 `Idle` `Walking` `Running` `Dance` `Sitting` `Wave` `Jump` `ThumbsUp` `Yes` `No`만 쓴다.

색을 칠하는 순회는 `o.material?.name === 'Main'`일 때만 `setColor`한다. 그 조건을 `||`로 넓히지 않는다. 이름표 글자색은 `paintNameTag` 캔버스에만 둔다. 발밑 링은 로컬 장식으로 두고 재질 색 경로에 넣지 않는다.

고양이·곰 메시 중 재질 이름이 `Main`인 것이 있으면 그 메시의 재질 이름을 `Coat`로 바꾼다. `Fur` `Belly` `Paw`는 그대로 둔다. `Ch14_Body`는 바꾸지 않는다.

모자 `hat_ribbon`은 `Head` 뼈에 붙인다. 뼈 탐색은 기존 bone lookup을 쓴다. 택시 `cab_yellow`는 탑승 중 택시 재질의 색만 바꾼다. `frame_streak`는 내 칸 테두리 색으로 `screens.js`가 이미 가진 림 색 인자에 전달한다. 재질 이름을 `Main`으로 만들지 않는다.

캐시 토큰 `20261116g`. `ts3d/avatars.js` import의 `?v=`를 이 토큰으로 올린다.
