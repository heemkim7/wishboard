# 메인 타워 축하 1분 (설계, 2026-11-27)

주인이 정한 것(2026-11-27 대화): 비게임 구조는 그대로 두고, 사람들이 "메인 전광판에 내 것을" 걸고 싶게 만든다. 선물 전광판을 메인 타워에 올리는 길을 둘 연다. **(A) 친구 응원 10곳**, **(B) 응원 포인트 2,000**. 자리는 하루 30. 공유 보상은 "친구가 내 선물 페이지에서 하트나 메시지를 남기면 +50, 하루 5명"으로 바꾼다. 돈 결제는 이번에 만들지 않는다.

바탕: `docs/revenue-review-2026-11-27.md`(상 2·3번), `docs/prime-screens.md`(명당 규칙), `docs/gift-board.md`(선물 전광판), `docs/point-sources-2026-11-27.md`(포인트 출처).

## 1. 왜 게임이 아닌가

- 입찰·빼앗기·추첨이 없다. 자리는 정해진 값(포인트 2,000) 또는 정해진 문턱(서로 다른 연결 10곳)으로, 남은 자리에서 먼저 고른 사람이 갖는다.
- 포인트는 여전히 팔지 않고, 보내거나 바꿀 수 없다. 메인 타워 1분은 돈으로 팔지 않는다(약관의 "명당은 돈으로 팔지 않습니다"는 그대로).
- 누가 몇 포인트를 냈는지, 누가 누구보다 먼저였는지는 어디에도 보이지 않는다. 보이는 것은 "지금 메인 타워: ○○의 생일"뿐이다.
- `docs/prime-screens.md`의 원칙 "명당은 포인트로 사지 않는다"는 이 설계에서 **메인 타워의 개인 축하 1분에 한해** 바뀐다. 팀 명당(목표 달성, 기념일, 밤 9시, 참여율)은 그대로 서로 다른 사람 수로만 얻는다. 게임위 질의서에 이 점을 묻는 질문을 더한다(7장).

## 2. 흐름

### 만드는 사람
1. `/gift`에서 선물 전광판을 만든다(지금과 같다).
2. 주인 화면 `/g/<id>`에 **"메인 타워에 올리기"** 카드. 그날 남은 자리 `N/30`, 두 버튼:
   - **친구 응원 모으기**: 진행 `k/10`과 공유하기. "친구가 이 페이지에서 하트를 누르거나 롤링페이퍼를 쓰면 한 칸씩 차요."
   - **2,000포인트로 올리기**: 계정만. 손님에게는 "계정을 연결하면 포인트로 올릴 수 있어요".
3. 자리 고르기(B는 바로, A는 10곳이 찬 뒤): 그 선물이 걸리는 시간 안의 1분 목록. 고를 수 없는 분은 회색(지난 분, 지금부터 5분 안, 정각 `:00`, 21:00~21:59, 이미 찬 분). 그날 30자리가 다 찼으면 "오늘 메인 타워는 매진이에요".
4. 고른 뒤: "20:30에 메인 타워에 올라가요" 카드와 카운트다운. B는 그 자리에서 포인트가 빠진다.

### 친구
- 링크를 열고 하트를 누르거나 롤링페이퍼를 쓴다. **하트는 그날 전에도 누를 수 있게 바꾼다**(지금은 그날에만 열린다).
- 진행이 10곳에 닿으면 만든 사람에게 알린다: 주인 화면의 카드가 "메인 타워가 열렸어요! 시간을 고르세요"로 바뀌고, 만든 사람이 알림을 켜 둔 기기가 있으면 푸시 한 번(광고가 아닌 거래 알림, 밤 시간 제한 없음).

### 그 1분
- 메인 타워 다섯 면(`MAIN_*`)이 모두 그 선물 전광판을 보인다(받는 사람 이름, 무슨 날, 한마디, 테마 색). 모든 사람이 같은 벽시계 1분에 같은 것을 본다.
- 광장 속보 한 줄: `🎉 지금 메인 타워: {받는 사람}의 {무슨 날}`. 포인트·방법(A/B)은 쓰지 않는다.
- 받는 사람 페이지와 주인 화면: 카운트다운 → 그 1분 동안 "지금 메인 타워에!"와 `광장에서 보기`(`/?gb=<id>`, 카메라를 메인 타워 정면에).
- 끝난 뒤: 주인 화면과 받는 사람 페이지에 "메인 타워에 올랐어요 · 20:30" 표시(보드가 남아 있는 7일 동안).

## 3. 규칙과 숫자

규칙은 순수 모듈 하나(`towerrules.js`, 새 파일, I/O 없음)에 둔다. Worker, 화면, 테스트가 같이 쓴다.

| 항목 | 값 | 이름(제안) |
| --- | --- | --- |
| 하루 자리 | 30 (KST 하루) | `TOWER.perDay` |
| 고를 수 없는 분 | 정각 `:00`(기념일 팀), 21:00~21:59(9시 팀), 지금부터 5분 안 | `TOWER.leadMs` |
| 고를 수 있는 범위 | 그 선물 전광판의 창(`GIFT.hours` 6시간) 안 | |
| A 문턱 | 서로 다른 네트워크(IPv6 /64) 10곳. 그 1분이 시작하기 전까지 하트 또는 롤링페이퍼를 남긴 연결. 만든 사람의 연결(만들 때의 네트워크 해시)은 세지 않는다 | `TOWER.friends` |
| A에서 세는 하트 | Turnstile이 켜져 있으면 사람 확인 토큰(`theart`, `HUMAN_ACTIONS`에 더함)이 붙은 하트만. 토큰이 없는 하트도 하트 수에는 그대로 들어간다 | |
| B 값 | 2,000 포인트, 계정만, 계정마다 30일에 한 번 | `TOWER.price`, `TOWER.gapDays` |
| 보드당 | 메인 타워 1분은 보드 하나에 한 번 | |
| 만든 사람당 | 하루 한 번(A·B 합쳐서) | |
| 팀과 겹칠 때 | 예약된 1분이 1,000명 목표 팀의 시간보다 먼저. 정각과 21시는 처음부터 팔지 않으므로 겹치지 않는다 | |
| 취소 | 보드가 신고로 가려지거나 지워지면 자리를 풀고, B는 2,000을 돌려준다(`grant_coins`). 운영자가 되살리면 자리는 이미 풀린 채로 둔다 | |
| 예산 hard | 예약·취소는 503 `busy`. 이미 잡힌 자리의 화면 표시는 사본으로 계속 | |

### 공유 보상 (바뀜)

| 항목 | 값 |
| --- | --- |
| 언제 | 내 선물 전광판 페이지(`/g/<id>`)에서 다른 네트워크의 사람이 처음 하트를 누르거나(위와 같은 토큰) 롤링페이퍼를 쓸 때 |
| 얼마 | +50, 보낸 사람(만든 사람)에게 |
| 상한 | 만든 사람마다 KST 하루 5명(250). 한 네트워크는 한 보드에 한 번. 만든 사람의 네트워크는 세지 않는다 |
| 누가 받나 | 만든 사람이 계정이든 손님이든 그 지갑으로(`grant_coins`는 actor id로 준다). 상한은 actor id마다 |
| 예전 보드 | 만들 때의 네트워크 해시가 없는 보드(이 기능 전에 만든 것)는 만든 사람 연결을 빼지 못한다. 그런 보드는 A와 공유 보상을 열지 않는다 |
| 지금의 공유 버튼 300 | 그대로 둔다(계정마다 평생 한 번, 2026-11-27) |

선물 전광판 페이지에서만 센다. 이 페이지는 링크로만 들어오므로 "공유해서 온 사람"이 분명하다. 광장 전광판의 응원과 소원 하트는 세지 않는다(약관 "내 전광판이 받은 응원이나 하트로는 포인트가 생기지 않습니다"를 이 한 가지 예외로만 고친다).

## 4. 만드는 방식

- **서버(`giftsrv.js`, Meter 인스턴스 `'gift'`, DO SQLite)**: 새 표 둘.
  - 예약 `gt(day, minute, g, how, actor, at)`: `how`는 `friends`/`points`. `(day, minute)` 유일, 하루 30줄 상한은 같은 트랜잭션에서 센다(동시에 두 명이 같은 분을 고르면 한 명만, 다른 사람은 409 `taken`과 새 목록).
  - 반응한 연결 `gn(g, net, at, paid)`: 보드·네트워크마다 한 줄. A 진행은 `count(*)`, 공유 보상은 `paid`.
  - B의 30일 간격과 만든 사람 하루 한 번은 같은 DO의 작은 표 `ga(actor, day)`.
- **경로(제안)**: `GET /rt/gift/<id>/tower`(남은 자리, 고를 수 있는 분, 내 진행), `POST /rt/gift/<id>/tower {minute, how}`(주인만, `how:'points'`는 계정과 Turnstile `tower`). 예약 결과는 `/rt/world`의 선물 목록 항목에 `tw`(그날의 분)로 붙인다.
- **포인트 빼기**: 지금 운영 DB의 `spend_plaza`는 30과 5,000만 받는다. `migrations/2026-11-27-tower-minute.sql`이 2,000을 더한다(나머지는 그대로). **주인이 SQL 편집기에서 돌린다.** 돌리기 전에는 RPC가 `그 금액은 쓸 수 없어요.`를 돌려주고, Worker는 이것을 "B 준비 중"으로 기억해(isolate 10분) 화면에 `포인트로 올리기는 준비 중이에요`를 보인다. A는 마이그레이션과 상관없이 동작한다. 포인트를 뺀 뒤 예약 쓰기가 실패하면 `grant_coins`로 돌려준다.
- **공유 보상 +50**: `grant_coins`로 만든 사람의 actor id에 준다. 하루 5명 기록은 `gn.paid`와 만든 사람별 하루 수. 만들 때 그 보드에 만든 사람의 네트워크 해시를 적는다(새 열).
- **메인 타워 그리기**: `ts3d/screens.js`가 그 분에 `MAIN_*` 다섯 면을 그 보드로 덮는다. 우선순위(`docs/prime-screens.md` 3장 6번)에 "예약된 축하 1분"을 정각 기념일 다음, 1,000명 팀 앞에 넣는다. 벽시계 기준이라 모든 사람에게 같다.
- **속보**: `ui.news`에 `TOWER` 종류를 더한다. 그 분이 시작할 때 광장에 있는 사람에게 한 번.
- **하트 앞당기기**: `/rt/gift/<id>/heart`를 그날 전에도 받는다(받는 사람 페이지가 열리기 전의 방문자 화면에 하트 버튼). 공개 전에는 하트 수를 보이지 않는 지금 규칙은 그대로.

## 5. 문서와 약관

- `legal.js`: 응원 포인트 조항의 쓰는 곳에 "메인 타워 축하 1분(2,000)"을 더하고 "명당에는 쓰지 않습니다"를 "응원 팀 명당에는 쓰지 않습니다"로. 얻는 곳에 공유 보상 +50(하루 5명)을 더한다. 시행일은 배포하는 날.
- `docs/prime-screens.md`: 1장 표와 3장 우선순위에 축하 1분, 머리말의 원칙 문장에 예외 한 줄.
- `docs/point-sources-2026-11-27.md`, `docs/gift-board.md`, `IMPLEMENTED.md`(새 절), `HANDOFF.md`.
- `docs/grac-inquiry.md`: 3장에 축하 1분 설명, 질문에 "무료로만 얻는 응원 포인트를 정해진 값으로 써서 메인 타워의 개인 축하 1분을 선착순으로 고르는 기능이 게임물 판단에 영향을 주는지" 한 줄.

## 6. 테스트와 확인

- 순수 규칙(`towerrules.js`): 고를 수 있는 분(정각·21시·5분·창 밖·지난 분), 하루 30, 보드당·만든 사람당·30일 간격, A 문턱(만든 사람 연결 제외, 같은 연결 두 번).
- 서버: 같은 분 동시 예약 하나만, 31번째 거절, B 마이그레이션 전 "준비 중"과 전후 모두 동작, 포인트 뺀 뒤 실패하면 돌려줌, 신고로 가려지면 자리 풀림·환불, 예산 hard 503, 공유 보상 하루 5명·한 연결 한 번·만든 사람 연결 제외·토큰 없는 하트는 안 셈.
- 화면: 주인 카드(남은 자리, 진행, 매진, 손님), 자리 고르기, 카운트다운, 메인 타워 덮기와 우선순위, 속보.
- 전체 테스트(`node --test test/*.test.mjs tools/account.test.mjs`) 실패 0.
- 본 세션의 로컬 확인: 375×812와 데스크톱에서 만들기 → 친구 10곳(시험 네트워크 해시) → 자리 고르기 → 그 분에 메인 타워. 운영 DB를 쓰는 로컬 서버이므로 B는 마이그레이션을 돌린 뒤 운영에서 주인이 확인한다.

## 7. 하지 않는 것

- 돈 결제와 '1시간 6명' 유료 상품. 결제가 열리면 같은 30자리 묶음에 붙인다.
- 선물 영상 화질(R2, 고정 해상도 렌더, 음악): `docs/revenue-review-2026-11-27.md` 상 1번으로 따로.
- 경매, 금액·순위 공개, 포인트 현금 교환.
- 메인 타워 1분 장면의 녹화·사진(그 1분에 광장에서 기존 녹화 버튼을 쓰면 된다. 자동 저장은 나중).
