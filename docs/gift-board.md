## 화면 배정 (어느 화면에, 얼마나)

- 쓰는 화면: 거리 칸 `STREET_1~50`과 분양 앞 `PLOT_1~18`(68개). 보타이 안의 `STREET_31~50`부터. **메인 타워(`MAIN_*`), 코너 큰 화면(`SUB_*`, 명당), 광고 화면(`AD_1~5`)에는 걸지 않는다.**
- 새 보드는 자기 6시간 동안 겹치는 보드가 가장 적은 화면으로 간다(`pickScreen`). 같으면 목록 순서. 한 화면에 동시에 4개(`GIFT.perScreen`)까지, 68 × 4 = 272개가 동시에 걸릴 수 있다. 다 차면 409 `full`과 가장 가까운 빈 시간(`nextFree`)을 돌려주고 화면이 그 시간으로 바꾸는 버튼을 보인다.
- 한 화면을 나눠 쓰면 9초(`GIFT.cycleMs`)씩 벽시계로 돈다(`turnOf`). 모든 사람이 같은 순간에 같은 보드를 보고, 보드마다 같은 몫을 받는다. 하트·인기로 더 오래 보이는 일은 없다.
- 광장에서: 플레이어가 켠 칸(점령해 켜진 칸)은 덮지 않는다. 그 칸의 선물은 비어 있는 가장 한가한 풀 화면으로 옮겨 보인다(`placeGifts`). 소원 카드와 밤 9시 소원왕 카드보다는 선물이 이긴다. 60초 장악(`air`)은 그대로 덮는다.
- `직접 가서 보기`(`/?gb=<id>`): 그 보드를 1분 동안 한 화면에 혼자 올리고(`pinGift`), 캐릭터를 그 앞에 두고 카메라를 맞춘 뒤 폭죽을 쏜다. 그날 0시부터 걸리기 전, 그리고 내려온 뒤 페이지가 남아 있는 7일 동안에는 이 기기에서만 같은 방식으로 보여 준다(`giftrules.js` `plazaLook`의 `replay`, 방과 Worker에 보내지 않는다. 2026-11-24). 그날 전이면 언제 걸리는지 알린다.

## 15초 영상

- **광장 녹화(진짜 영상)**: `gift.js`가 `#view`를 9:16 기둥으로 바꾸고 HUD를 숨긴 뒤 `world.giftShow`(높은 하늘 → 거리로 내려오는 두 번의 미끄러짐 → 정면에서 멈춤, 폭죽 여섯 번, 그 앞에서 환호하는 캐릭터 6마리. 이 캐릭터는 이 기기에만 있고 아무에게도 보내지 않는다)를 돌린다. 그리는 프레임마다(`world.onFrame`, 렌더 직후) 720×1280 캔버스에 옮기고 첫 문구, 끝 문구, 워터마크(`WISH BOARD · 무료`, `가상 광장 · 실제 타임스퀘어와 무관`)를 얹어 `MediaRecorder`로 15.2초 녹화한다. 형식은 `video/mp4;codecs=avc1.42E01E`를 먼저, 안 되면 WebM(`RECORD_TYPES`). 1.8Mbps. 탭을 숨기면 멈추고 다시 하라고 한다(숨은 탭은 프레임을 그리지 않는다).
- **그려진 영상(대체·미리보기)**: `giftfilm.js`. 2D 캔버스에 원근으로 그린 네온 거리를 날아가 끝 건물의 전광판(그 보드 그림)에 닿고, 폭죽·색종이·쥐·고양이·곰 군중이 환호한다. 시간의 순수 함수라 매번 같고, 보드 id로 장면이 정해진다. 저장된 영상이 없거나 이 브라우저가 그 형식을 못 틀면 받는 사람 페이지가 이것을 튼다. "영상 저장"은 이것을 이 기기에서 녹화한다.
- 잰 값(로컬 서버, 헤드리스 Chrome, 2026-11-23):
  - 받는 사람 페이지(390×844, 4G 9Mbps/60ms, CPU 4배 느리게): 첫 그림 0.42초, `load` 1.34초, 영상 무대 1.44초. 받은 양 321KB(저장된 MP4 157KB 포함, 모듈과 HTML은 약 160KB, 압축 전).
  - 그려진 영상 녹화: MP4(H.264) 3.4MB, 15.0초, 720×1280, 15.2초 걸림.
  - 광장 녹화(데스크톱 GPU): 120fps, MP4 2.9~3.0MB, 페이지 열기부터 결과까지 약 24초(도시 불러오기 포함). 올리기 3.1MB가 로컬 R2에 들어가고 Range 206으로 다시 나온다.
  - 휴대폰 실기에서는 재지 못했다(아래 "확인하지 못한 것").

### R2 켜기 (주인이 할 일, 이 코드는 바인딩 없이도 동작한다)

```sh
npx wrangler r2 bucket create wishboard-media --location apac
# 남는 파일 안전망: 45일 지난 gift/ 아래 파일 지우기(보드는 그날+7일에 같이 지운다)
npx wrangler r2 bucket lifecycle add wishboard-media gift-expire gift/ --expire-days 45
```

`wrangler.jsonc`에 더한다(`durable_objects` 위):

```jsonc
"r2_buckets": [ { "binding": "MEDIA", "bucket_name": "wishboard-media" } ],
```

그리고 `npx wrangler deploy`. 바인딩이 생기면 주인 화면이 "받는 사람 페이지에 올라가요"로 바뀌고 `/rt/admin/gift`의 `media`가 `true`가 된다. 버킷은 공개로 열지 않는다(영상은 Worker를 거쳐 나간다). lifecycle 명령의 인자 순서는 wrangler 버전에 따라 `npx wrangler r2 bucket lifecycle add --help`로 확인한다.

비용: 무료 10GB 저장, 쓰기(Class A) 월 100만, 읽기(Class B) 월 1,000만. 보드 1,000개에 영상 3MB면 3GB이고 7~8일마다 비워진다. 재생 한 번에 Worker 요청 1~3개(Range)와 R2 읽기 2~6번.

| `msg`, `video`, `report` | 롤링페이퍼 줄, 처음 올린 영상, 신고 |
| `reply` / `ev:reply` | 답장을 처음 받은 보드 수(보드마다 한 번. 답장을 지우고 다시 걸어도 다시 세지 않는다) / 답장 버튼을 누른 기기(기기·보드·하루마다 한 번) |
| `ev:film` `ev:play` `ev:done` `ev:save` `ev:go` `ev:share` `ev:cta` | 그려진 영상 재생, 저장 영상 재생, 끝까지 봄, 영상 저장, 직접 가서 봄, 공유, 나도 걸기 (기기·보드·하루마다 한 번, 주인 자신의 미리보기는 세지 않는다) |
| `ladder`, `pick:1~3`, `notify:1~3` | 가격표를 본 보드, 단마다 고른 보드, 알림 신청 |

- **K**(E2) = `made_ref ÷ made`. 보드당 방문자 = `view` 합 ÷ 보드 수(관리자 표의 잠금 갈래별 줄).
- **E1 관심률** = 유료 단을 하나라도 고른 보드 ÷ 만든 보드. 고름은 계정이나 보드와 이어 저장하지 않으므로 "보드당 한 번"은 그 기기에서만 지킨다(`kts_gint`).
- **E3**: Worker 변수 `GIFT_E3`가 `1`이면 보드 id로 반을 나눠 반은 메시지를 바로 보인다(`lk` 0). 기본은 모두 잠금. 관리자에 갈래별 보드 수, 보드당 방문자, 그날 방문자, 보드당 메시지가 나온다.
- 비컨은 isolate에 모았다가 25개 또는 30초마다 DO 한 번으로 보낸다. isolate가 사라지면 모은 것을 잃는다(요청 집계와 같다).

## 개인정보와 보유 기간 (처리방침 반영용, `legal.js`는 다른 작업이 고친다)

`legal.js`(2026-11-23 개정)의 "선물 전광판과 롤링페이퍼", "알림", "탈퇴"와 맞춘 것:

| 항목 | 저장하는 것 | 보이는 사람 | 지우는 때 |
| --- | --- | --- | --- |
| 선물 전광판 | 만든 계정·손님 번호, 받는 사람을 부를 이름(연락처 아님), 보내는 사람 이름, 날짜·시간, 문구, 꾸미기, 네트워크 해시(한도용) | 문구와 이름은 광장과 링크를 연 누구나. 계정 번호와 네트워크는 아무에게도 | 그날(KST)이 끝나고 7일 뒤, 주인이 지울 때, 탈퇴 |
| 답장 표시 | 답장 보드의 id 하나(원래 보드의 `re` 열) | 원래 보드의 주인만 | 답장 보드가 지워질 때, 원래 보드와 함께 |

| 유료 관심(고름) | 날짜별 합계만(계정·보드와 잇지 않는다) | 관리자 | 400일 |
| 열리면 알림 | 계정·손님 번호와 단, 동의 시각. 같은 푸시 구독을 쓴다. 이메일은 받지 않는다 | 관리자(수만) | 60일 동안 다시 누르지 않으면, 탈퇴. 푸시 구독 자체는 기존 규칙(60일, 해지, 탈퇴) |

- 탈퇴(`/rt/auth/withdraw` → `forgetActor` → `giftForget`): 그 계정(과 이어진 손님)의 보드와 그 위의 모든 줄(다른 사람이 쓴 줄 포함), 그 계정이 다른 보드에 쓴 줄(그 보드의 줄 수도 고친다), 영상(R2), 알림 신청을 지운다. 남의 보드와 남이 쓴 줄은 남는다.
- 계정 연결(`/rt/auth/merge` → `giftMove`): 손님의 보드, 쓴 줄, 알림 신청을 계정으로 옮긴다. 다시 해도 바뀌지 않는다. 같은 단의 신청이 둘 다 있으면 계정 쪽이 남는다.
- "열리면 알림"은 광고성 정보다: 누를 때 따로 동의 상자(체크해야 버튼이 켜진다), 서버도 `consent: true` 없이는 받지 않는다. 보낼 때 앞에 `(광고) `가 붙고(`worker.js` `pushText`가 그 접두어 없는 글은 보내지 않는다), 한국 시간 21:00~08:00에는 관리자 보내기가 409 `quiet`다. 한 계정에 한 번. 관리자 화면에서 한 번에 10명씩(무료 플랜의 하위 요청 한도) 보낸다.
- 답장 알림(`giftreply`)은 광고가 아닌 정보성 알림이다. 보드에 답장이 처음 걸릴 때 원래 보드의 주인에게 보내고(보드마다 한 번뿐. `gr`의 `rn:<보드 id>`가 기억한다), 한국 시간 21:00~08:00에는 보내지 않는다. 같은 푸시 구독을 쓴다. 알림의 주소는 `/g/<보드 id>?o=1`이고 `?o=1`은 주인 화면을 청한다(주인인지는 Worker가 토큰으로 정한다).

## 하지 않은 것 / 확인하지 못한 것

- 답장 알림의 실제 푸시 전송과 알림을 눌렀을 때의 이동(로컬에는 `VAPID_PRIV`가 없다). 글·링크·한 번만·조용한 시간은 테스트에서 암호를 풀어 확인했다. `영상 먼저`는 R2 바인딩이 없어 화면으로 보지 못했다.
- 결제, 이메일 수집, 유료 단의 실제 기능(큰 화면, 24시간, 9시 퍼레이드). 가격표는 보이기만 한다. 무료 단의 "결제가 열린 뒤 받는 사람 페이지의 작은 광고"는 아직 없다(가격표에 앞날의 일로 적었다).
- 사진, 카카오 SDK 공유(받는 쪽은 `navigator.share`와 링크 복사. 광장의 기존 카카오 공유와는 따로).
- 실제 휴대폰(iOS 사파리, 안드로이드 크롬)에서 녹화 형식, 녹화 중 프레임 수, 올리기 시간을 재지 못했다. iOS 사파리의 `MediaRecorder` MP4, 인앱 브라우저(카카오톡)의 `captureStream`이 되는지 확인해야 한다. 안 되면 버튼이 "이 브라우저에서는 영상을 만들 수 없어요"를 보인다.
- 운영 Turnstile에서 `gift`·`gmsg`·`gvid` 토큰이 실제로 통과하는지(로컬은 꺼져 있었다).
- 결제 오픈 알림의 실제 푸시 전송(로컬에는 `VAPID_PRIV`가 없다). 조용한 시간 거절, 한 계정 한 번, `(광고)` 접두어 검사는 테스트와 로컬에서 확인했다.
