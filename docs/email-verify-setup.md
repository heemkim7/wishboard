# 이메일 인증(6자리 코드) 켜기 — 사장님 설정 안내 (2026-11-22)

사장님 요청: "이메일 연결이 실제 메일 인증 없이 가입돼요. 메일 인증이 필요해요. 구현해 줄 수 있나요? Supabase에서 이메일은 켜져 있어요."

게임 코드는 준비돼 있다. Supabase의 **Confirm email** 스위치 하나를 따른다.

- **꺼져 있으면(지금)**: 가입하면 바로 로그인·연결된다. 지금과 같다.
- **켜면**: 가입하면 그 주소로 6자리 코드가 간다. 로그인 시트가 그 자리에서 `메일로 보낸 6자리 코드를 입력하세요`로 바뀌고, 코드를 넣어야 계정이 만들어지고 손님의 코인·전광판이 연결된다. 메일의 링크를 누르는 방식이 아니라 **같은 게임 창에 코드를 넣는 방식**이다. 메일 앱에서 링크를 누르면 다른 브라우저가 열리는 일이 많아, 코인을 가진 손님이 있는 창에서 연결되지 않기 때문이다.

스위치는 배포 없이 바로 적용된다(게임이 로그인 시트를 열 때 Supabase에 물어본다). 아래 순서대로 하면 된다.

**지금 결정(2026-11-22 저녁): 메일 확인은 당분간 끈 채로 둔다(SMTP가 없다).** 그동안 메일 확인 없이 찍어 낸 계정이 코인을 모으는 길은 Turnstile이 막는다. Turnstile을 켜면 연결 보상 300, 공유 보너스 300, VIP 코드는 받을 때마다 사람 확인이 있어야 한다(`docs/bot-protection.md` 6번). SMTP를 단 뒤 아래대로 켜도 그 확인은 그대로 둔다.

## 먼저 알아 둘 것

1. **이 코드가 배포된 뒤에 켠다.** 예전 코드가 돌고 있을 때 켜면 가입이 `가입은 기록됐지만 이 창에서 바로 로그인되지 않았어요…`로 끝나고 코드 칸이 없다.
2. **SMTP를 먼저 단다.** Supabase가 기본으로 주는 메일은 프로젝트 팀원 주소로만 가고 한 시간에 몇 통밖에 못 보낸다. SMTP 없이 켜면 일반 이용자는 `지금은 이 주소로 확인 메일을 보낼 수 없어요. 구글로 연결해 주세요.`를 보고 가입하지 못한다.
3. **켜면 아이디 가입은 막힌다.** 아이디 가입은 `아이디@id.wishboard.dev`라는 가짜 주소를 쓰므로 코드 메일을 받을 수 없다(전에 확인이 켜져 있을 때 아이디 가입이 안 되던 이유다). 그래서 확인이 켜져 있으면 가입 칸이 `이메일 주소`로 바뀌고, 아이디를 적으면 Supabase에 보내지 않고 `지금은 아이디로 새로 가입할 수 없어요. 이메일 주소로 가입하거나 구글로 연결해 주세요. 만들어 둔 아이디로는 로그인할 수 있어요.`를 보인다. **이미 만든 아이디의 로그인은 그대로 된다.**
4. 구글 로그인은 바뀌지 않는다(구글이 이미 주소를 확인했다).

## 1. 메일 보낼 곳(SMTP) 고르기

| | Gmail 앱 비밀번호 | Brevo | Resend |
| --- | --- | --- | --- |
| 필요한 것 | 2단계 인증을 켠 Gmail 계정 | 가입 + **내 도메인**(DNS를 고칠 수 있는 주소) | 가입 + **내 도메인** |
| 보내는 사람 | 그 Gmail 주소 | 내 도메인 주소(예: `no-reply@내도메인`) | 내 도메인 주소 |
| 무료 한도(바뀔 수 있음) | 하루 약 500명 | 하루 300통 | 하루 100통, 한 달 3,000통 |
| 장점 | 도메인 없이 오늘 바로 | 도메인 인증을 하면 스팸함에 덜 간다 | 설정이 간단하다 |
| 단점 | 개인 Gmail이 보내는 사람으로 보인다. 한도를 넘으면 그 Gmail의 보내기가 하루까지 막힌다 | 도메인이 없으면 쓸 만하지 않다 | 도메인 인증 전에는 내 주소로만 보내진다 |

어느 쪽이든 가입하는 사람의 메일 주소가 그 업체를 거쳐 나간다. 고른 뒤 알려 주면 개인정보처리방침(`legal.js`)에 '인증 메일 발송: <업체>' 한 줄을 더한다(지금 방침에는 없다).

`studio.wishboard.workers.dev`는 Cloudflare 주소라 DNS를 고칠 수 없다. 도메인이 없으면 **Gmail 앱 비밀번호로 시작**하고, 도메인을 산 뒤 Brevo나 Resend로 옮기는 것을 권한다. 옮길 때는 2번의 SMTP 칸만 바꾸면 된다.

### Gmail 앱 비밀번호 만들기
1. 보내는 데 쓸 Gmail로 로그인한다(개인 주 계정보다 게임 전용 Gmail을 새로 만드는 편이 낫다).
2. Google 계정 → 보안 → **2단계 인증**을 켠다.
3. https://myaccount.google.com/apppasswords 에서 이름(예: `Supabase`)을 적고 만든다. 16자리 앱 비밀번호가 한 번 보인다. 공백 없이 적어 둔다.

### Brevo / Resend를 쓸 때
- Brevo: 도메인을 Senders, Domains에서 인증(DKIM, DMARC)하고, SMTP & API에서 SMTP 키를 만든다. 호스트 `smtp-relay.brevo.com`, 포트 `587`, 사용자 이름은 Brevo가 보여 주는 SMTP 로그인, 비밀번호는 SMTP 키.
- Resend: Domains에서 도메인을 인증하고 API 키를 만든다. 호스트 `smtp.resend.com`, 포트 `465`, 사용자 이름 `resend`, 비밀번호는 API 키(`re_`로 시작).

## 2. Supabase에 SMTP 넣기

Supabase 대시보드 → 프로젝트 **wishboard** → Authentication → **Emails** → **SMTP Settings** → Enable custom SMTP 켜기.

| 칸 | Gmail로 할 때 |
| --- | --- |
| Sender email | 그 Gmail 주소 |
| Sender name | `WISH BOARD` |
| Host | `smtp.gmail.com` |
| Port number | `465` (안 되면 `587`) |
| Minimum interval between emails | `60` 초(게임의 `코드 다시 보내기` 기다림과 같다) |
| Username | 그 Gmail 주소 전체 |
| Password | 1번의 16자리 앱 비밀번호 |

저장한다. (대시보드의 글자나 위치는 조금 바뀔 수 있다.)

## 3. 메일 내용 바꾸기 — "Confirm signup"

Authentication → Emails → **Templates** → **Confirm signup**.

- 제목(Subject):

```
WISH BOARD 가입 확인 코드 {{ .Token }}
```

- 본문(Message body, 아래를 통째로 붙여 넣는다):

```html
<div style="margin:0;padding:24px 12px;background:#f2f4fa;font-family:'Apple SD Gothic Neo','Malgun Gothic',sans-serif;color:#1d2140">
  <div style="max-width:420px;margin:0 auto;background:#ffffff;border-radius:14px;padding:28px 24px;text-align:center">
    <p style="margin:0 0 4px;font-size:13px;color:#5b6180">WISH BOARD · 타임스퀘어 K-점령전</p>
    <h1 style="margin:0 0 18px;font-size:20px;line-height:1.4">가입 확인 코드</h1>
    <p style="margin:0 0 14px;font-size:15px;line-height:1.6">게임 화면의 코드 칸에 아래 6자리 숫자를 입력하세요.</p>
    <p style="margin:0 0 18px;padding:14px 0;border-radius:10px;background:#f2f4fa;font-size:36px;font-weight:800;letter-spacing:10px;font-family:Consolas,Menlo,monospace;color:#1d2140">{{ .Token }}</p>
    <p style="margin:0 0 6px;font-size:13px;line-height:1.6;color:#5b6180">받는 주소: {{ .Email }}</p>
    <p style="margin:0 0 6px;font-size:13px;line-height:1.6;color:#5b6180">코드는 한 시간 동안 쓸 수 있어요. 새 코드를 받으면 이 코드는 쓸 수 없어요.</p>
    <p style="margin:0;font-size:13px;line-height:1.6;color:#5b6180">가입한 적이 없다면 이 메일은 무시하세요. 아무 일도 일어나지 않아요.</p>
  </div>
</div>
```

- `{{ .ConfirmationURL }}`(링크)은 **넣지 않는다**. 링크는 다른 브라우저에서 열려 코인을 가진 손님과 연결되지 않을 수 있다. 예전 메일의 링크를 누른 사람도 게임이 받아 준다(아래 '예전 링크').
- 같은 화면의 **Email OTP Expiration**(Authentication → Sign In / Providers → Email 안에 있을 수 있다)은 `3600`초(한 시간, 위 문구와 같다), **Email OTP Length**는 `6`으로 둔다. 게임 화면이 "6자리"라고 말한다.
- 다른 템플릿(Magic link, Reset password, Invite 등)은 게임이 쓰지 않는다.

## 4. 보내기 한도 — Rate Limits

Authentication → **Rate Limits** → **Rate limit for sending emails**(시간당, 프로젝트 전체). SMTP를 달면 기본 30이다.

- 가입 한 번에 메일 한 통, `코드 다시 보내기` 한 번에 한 통이다.
- Gmail(하루 약 500명): 시간당 `30`~`40`. 한도에 닿으면 가입하는 사람은 `지금은 확인 메일이 너무 많이 나갔어요. 잠시 뒤에 다시 해 주세요.`를 본다. Gmail 자체 한도를 넘으면 `확인 메일을 보내지 못했어요…`가 나오고 그 Gmail은 하루까지 못 보낸다.
- Brevo 무료(하루 300): 시간당 `30`. Resend 무료(하루 100): 시간당 `15`~`20`.
- 코드 확인(Token verifications) 한도는 기본값 그대로 둔다(코드 맞히기 반복을 막는다).

## 5. 주소 설정 — URL Configuration

Authentication → **URL Configuration**.

- Site URL: `https://studio.wishboard.workers.dev` (지금과 같다)
- Redirect URLs: `https://studio.wishboard.workers.dev/**` 가 있어야 한다(`/oauth` 구글 로그인과, 예전 메일 링크가 돌아오는 `/?mail=1`을 함께 덮는다). `http://localhost:8790/**`는 그대로 둔다.

새 템플릿에는 링크가 없어서 이 설정은 예전 메일과 기본 템플릿에만 쓰인다.

## 6. 켜기 전에 메일이 가는지 보기

확인이 꺼진 동안에는 가입해도 메일이 가지 않으므로, 대시보드에서 한 통 보내 본다.

- Authentication → **Users**에서 사장님 본인 계정 줄의 메뉴(⋯) → **Send magic link**(또는 Send password recovery). 그 메일이 받은편지함(또는 스팸함)에 오면 SMTP는 된다. 메일 안의 링크는 누르지 않아도 된다.
- 안 오면: 2번의 앱 비밀번호, 포트(465 ↔ 587), Gmail 2단계 인증을 다시 본다. Authentication → Logs(또는 Logs Explorer의 auth 로그)에 SMTP 오류가 남는다.

## 7. 켜기

Authentication → **Sign In / Providers** → **Email** → **Confirm email** 켜고 저장.

## 8. 켠 뒤 본인 주소로 시험

실서비스에서 진짜 계정이 만들어지므로 사장님이 직접 한다. 시크릿 창을 쓰면 기존 로그인과 섞이지 않는다.

1. 시크릿 창으로 https://studio.wishboard.workers.dev 를 열고 손님으로 입장한다.
2. `계정 연결 +300` → `처음이면 가입`. 첫 칸이 `이메일 주소`로 보이면 게임이 확인이 켜진 것을 안 것이다.
3. 본인 메일(가능하면 Gmail이 아닌 네이버·다음 주소도 하나 더), 비밀번호 6자 이상, 동의 체크 → `가입하고 연결`.
4. 시트가 `메일로 보낸 6자리 코드를 입력하세요`, `보낸 곳 <주소>`, 코드 칸, `확인하고 연결`, `코드 다시 보내기 (60초)`로 바뀌는지 본다.
5. 메일이 오는지(스팸함 포함), 제목과 본문에 6자리 코드가 크게 있는지 본다.
6. 틀린 숫자 6개 → `코드가 맞지 않거나 시간이 지났어요…`.
7. 60초 뒤 `코드 다시 보내기` → 새 메일이 오고, 먼저 받은 코드는 더 이상 통하지 않는다.
8. 새 코드 → `계정을 연결했어요. +300코인` 토스트, 지갑 숫자가 맞는지.
9. 설정에서 로그아웃 → 같은 메일·비밀번호로 로그인 → 된다.
10. 확인 안 된 주소의 로그인: 다른 메일로 가입만 하고 코드를 넣지 않은 채 새로고침 → `이미 계정이 있어요 · 로그인`으로 그 주소 로그인 → 코드 단계(`가입한 주소`, `새 코드 받기`)로 가는지.
11. 아이디(예: `test1234`)로 가입 → 막히는 문구. 예전에 만든 아이디가 있으면 로그인은 되는지.
12. 시험 계정 정리: 각 계정으로 설정 → 탈퇴(로그인 정보까지 지워진다). 코드를 넣지 않은 가입은 Authentication → Users에서 그 줄을 지운다.

## 되돌리기

**Confirm email**을 끄면 바로 예전처럼 가입 즉시 로그인된다(배포 필요 없음). 켜 둔 동안 코드를 넣지 않은 가입은 미확인으로 남는다. 아래 '주의'를 본다.

## 예전에 가입한 계정은 어떻게 되나

- **확인이 꺼져 있던 동안 가입한 계정(이메일·아이디)**: Supabase가 가입 순간 '확인됨'으로 적어 두었다. 켠 뒤에도 그대로 로그인된다. 그 주소가 정말 그 사람 것인지는 확인되지 않은 채이고, 다시 확인을 받게 하는 기능은 없다.
- **예전에 확인이 켜져 있던 동안 가입하고 확인을 못 한 계정**(HANDOFF 기준 1개, 코인 마이그레이션 결과의 `메일 확인이 안 끝난 옛 가입 N개`): 켠 뒤 그 주소로 로그인하면 코드 단계로 가고 `새 코드 받기`로 확인할 수 있다(진짜 메일 주소일 때). 아이디였다면 메일을 받을 수 없으니 코인 마이그레이션 2부(주석)로 확인 처리하거나 Authentication → Users에서 지운다.
- **주의(지금, 확인이 꺼진 상태)**: Supabase는 확인이 꺼져 있을 때, 확인 안 된 주소로 누가 **다시 가입**하면 비밀번호를 묻지 않고 그 기존 계정을 확인 처리하고 로그인시킨다(Supabase Auth의 동작이다). 그래서 위의 미확인 옛 가입은 그 주소를 아는 사람이 가져갈 수 있다. 확인을 켜면 이 길은 그 주소로 가는 코드가 되어 닫힌다. 켜기까지 오래 걸리면 그 줄을 2부로 확인 처리하거나 지우는 편이 안전하다.
- 같은 이유로, 확인이 켜진 뒤에는 남이 먼저 내 주소로 가입해 둔 경우에도 코드를 받은 사람이 가입 때 적은 비밀번호가 그 계정의 비밀번호가 된다(게임이 코드 확인 직후 비밀번호를 한 번 다시 정한다).

## 예전 링크 메일

템플릿을 바꾸기 전에 나간 메일, 또는 기본 템플릿의 링크를 누르면:

- 가입한 그 브라우저면 그대로 로그인되고 평소처럼 손님이 연결된다.
- 다른 브라우저면 주소는 확인되고 `메일 확인이 끝났어요. 가입하던 창에서 [확인하고 연결]을 누르거나, 여기서 로그인해 주세요.`가 뜬다. 가입하던 창에서 코드 칸을 비운 채 `확인하고 연결`을 눌러도 연결된다(그 창이 비밀번호로 로그인한다).
- 시간이 지난 링크면 `메일 링크가 만료됐거나 이미 쓰였어요. 이메일로 로그인하면 새 코드를 받을 수 있어요.`가 뜬다.
